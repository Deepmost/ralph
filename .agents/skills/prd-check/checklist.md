# PRD 审核检查清单

按 PRD 模板章节组织的逐条检查项。审核时对每一项判定：✅ 通过 / ⚠️ 待改进 / ❌ 缺失或错误，并定位到具体章节。

## 1. 文档基本信息
- [ ] 文档名称、版本号、作者、时间是否齐全
- [ ] 文档状态是否标注（草稿/评审中/已确认/已上线）

## 2. 背景与目标
- [ ] 业务背景是否说清「为什么做」，有事实支撑而非空泛
- [ ] 当前问题是否具体、可定位
- [ ] **需求目标是否可量化**（有指标，如转化率、工单量、耗时），无量化为 P0/P1
- [ ] 目标与背景问题是否对应（解决的正是提出的问题）

## 3. 需求范围
- [ ] 本期「包含」项是否明确、颗粒度合适
- [ ] **本期「不包含」是否明确**（边界缺失易导致范围蔓延，为 P1）
- [ ] 影响范围（端/用户/系统/流程）是否完整评估

## 4. 用户角色与使用场景
- [ ] 角色是否覆盖所有相关方（含管理员、运营、客服等）
- [ ] 每个角色的使用场景与用户目标是否清晰
- [ ] 场景是否与后续功能需求对应

## 5. 业务流程
- [ ] **主流程是否完整**，每步有明确触发条件与结果（缺失为 P0）
- [ ] 异常流程是否覆盖关键失败分支（触发条件/系统处理/用户提示齐全）
- [ ] 状态流转表是否闭环（无孤立状态、无缺失的流转路径）
- [ ] 流程图与文字描述、与功能需求是否一致

## 6. 功能需求
- [ ] 功能点是否分模块列出并标注优先级（P0/P1/P2）
- [ ] 每个功能点是否包含：页面入口/展示规则/操作规则/校验规则/保存逻辑/异常处理
- [ ] **校验规则是否明确可执行**（字段/状态/权限/业务条件），含边界值
- [ ] 保存逻辑是否说清数据如何处理、是否同步其他系统
- [ ] 功能描述是否无歧义（无「等」「类似」「大概」等模糊词）

## 7. 页面与交互说明
- [ ] 原型/设计稿链接是否提供
- [ ] 页面元素的展示规则与交互规则是否说明
- [ ] **页面状态是否覆盖**：默认/加载/空/错误/成功

## 8. 字段与数据规则
- [ ] 字段是否标明类型、是否必填、默认值、规则说明
- [ ] 字段是否与功能需求、接口、埋点参数一致
- [ ] 关键字段的取值范围/格式/长度约束是否明确

## 9. 业务规则
- [ ] 业务规则是否完整、无相互矛盾
- [ ] 规则是否覆盖边界与特殊场景（如次数限制、锁定状态、并发）
- [ ] 规则是否与流程、字段、验收标准一致

## 10. 权限与角色控制
- [ ] 各角色的权限是否明确（可见/可操作范围）
- [ ] 是否存在越权风险点
- [ ] 权限规则是否与功能、异常提示一致

## 11. 异常场景与提示文案
- [ ] 是否覆盖：无权限/网络异常/数据为空/参数错误等
- [ ] 提示文案是否明确、统一、对用户友好
- [ ] 异常处理是否与功能需求中的异常处理一致

## 12. 数据埋点与统计
- [ ] 核心指标是否定义（曝光/点击/提交/成功/失败/转化）
- [ ] 埋点事件是否含事件名、触发时机、事件参数
- [ ] 埋点是否能支撑需求目标的量化验证

## 13. 非功能需求
- [ ] 性能要求是否量化（加载时间、接口响应时间）
- [ ] 安全要求是否明确（权限校验/脱敏/防刷/防越权）
- [ ] 兼容性、稳定性（兜底/降级/重试）、日志是否说明

## 14. 接口与系统依赖
- [ ] 依赖系统是否列明及依赖内容
- [ ] 核心接口是否说明请求方式、调用时机、业务作用
- [ ] 接口是否与功能流程、字段规则对应

## 15. 验收标准
- [ ] **验收标准是否可量化、可测试**（缺失或不可测为 P1）
- [ ] 是否与功能需求一一对应，覆盖正常/异常/边界
- [ ] 是否明确「做到什么程度算完成」

## 16. 上线与灰度方案
- [ ] 上线时间、灰度范围是否明确
- [ ] 开关配置、数据迁移、回滚方案是否考虑
- [ ] 运营配置、客服话术是否准备

## 17. 风险与待确认事项
- [ ] 已知风险/待确认项是否列出并指定负责人与状态
- [ ] 风险是否有应对或跟踪机制

## 18. 附录
- [ ] 原型/设计稿/竞品/相关文档/名词解释等是否补充（非阻断）

## 跨章节一致性专项（重点）
- [ ] 功能需求 ↔ 字段规则 ↔ 接口 ↔ 埋点：四者字段口径是否一致
- [ ] 主流程 ↔ 状态流转 ↔ 异常流程：是否互相覆盖、无矛盾
- [ ] 需求目标 ↔ 验收标准 ↔ 埋点指标：目标能否被验收和数据验证
- [ ] 用户角色 ↔ 权限控制 ↔ 使用场景：角色定义是否贯穿一致
- [ ] 本期范围（含不做） ↔ 功能需求：是否存在范围外功能或范围内遗漏
